# TUI Views Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the TUI the CLI's read side (status, plan, detect facts), the missing apply options, and gh-dash-grade view/refresh polish, in five shippable slices.

**Architecture:** The compositor gains a view row (Modules · Status · Plan · Profile, layout A). Each new view is a session-lived model fed by the existing service reads area through the widened `Reads` consumer interface; the modal stack, one `esc` rule, one binding table, and the apply session flow do not change shape.

**Tech Stack:** Go, charm v2 (bubbletea/bubbles/lipgloss), service layer (`internal/service`), drift (`internal/drift`), golden frame tests at 100x30 and 64x24.

**Spec:** [docs/superpowers/specs/2026-10-18-tui-views-design.md](../specs/2026-10-18-tui-views-design.md)

## Global Constraints

- TDD first per repo AGENTS.md: failing test before production code; tests cover behavior at the public seam (compositor messages, service area calls), not plumbing.
- Verification is `go test ./...` and `go vet ./...` (never `go test -run` to skip); use `GOCACHE=/tmp/gocache` in this sandbox.
- Every slice has one issue in `docs/issues/` (0107–0111), updates `docs/product/tui.md` and `docs/log.md` in its closing commit, and commits only when its tests pass. No co-author tags.
- All user text in ASD-STE100 plain English; every new key goes in the one binding table (`keyTable()` in `internal/tui/keymap.go`) so footer and `?` help render from it.
- ADR-0008 holds: the TUI reads only through narrow consumer interfaces over `internal/service`; no domain-package reads from `internal/tui`.
- Loads stay tolerant in the shell (`profile.LoadTolerant`); strict load stays the apply path.
- No new config file, no user keybindings, no shell-command keys (spec non-goals).

## Review Focus

1. A sudo password prompt must never reach the altscreen (Status probing of root-owned files) — pinned in Task 6 by the elevation-gate test.
2. A broken `module.toml` must never let Status read as "no drift" for a module that did not resolve — pinned in Task 6 (tolerant-load notice test).
3. Changing the yank set must not leave Status/Plan showing the old scope as current — pinned in Task 7 (stale-mark test).
4. A slow or hung probe must not freeze the shell (reads are `tea.Cmd`s; spinner keeps ticking) — pinned in Task 6 (pending-state test with a blocked probe).
5. The view row must not break the 64x24 frame or the 60x12 too-small guard — pinned in Task 3 (small-frame golden).
