* **Fixed (mise/paru output lost its color when streamed)**: `runOp` (the single place dotdrift runs mise operations) previously teed stderr through `io.MultiWriter(errW, &errBuf)` to inspect it for permission-denied messages. A `MultiWriter` is not an `*os.File`, so `os/exec` gave the child a **pipe** for stderr → the child's `isatty(2)` was false → mise (and its children: paru, tool installs) disabled color. mise/paru emit zero ANSI when piped and honor no force-color override (verified), so the only fix is to never pipe. `runOp` now wires the child's stdout/stderr **straight to the destination** (`cmd.Stderr = errW`), never through a MultiWriter — when the destination is a terminal `*os.File` the child inherits the fd and keeps its color (verified: inherited terminal fd → `isatty(2)=yes`, pipe → `no`). A failure returns the bare exec error (output already streamed live). The one consumer of captured stderr — `systemFilesStep`'s sudo retry on mise's "Permission denied" — is replaced by a **writability pre-flight**: before choosing elevation, `systemTargetsUserWritable` walks each system target to its nearest existing ancestor and checks the write-access bit (`unix.Access(W_OK)`); any non-writable target ⇒ converge elevated in one sudo pass. This deleted the now-dead `streamError`/`capturedStderr`/`IsPermissionDenied` machinery. * **Added (dotfile edit entries — line/block/template/source-edit partial edits)**: `[dotfiles]` now supports edit entries — partial edits to a file something else owns — keyed by `<file-path>/<edit-id>` (the last slash splits file path from edit id). Four forms: `line` (ensure an exact line exists), `block` (optionally `comment`-prefixed, wrapped in mise marker delimiters `>>> mise:<id> >>>` / `<<< mise:<id> <<<`), `source`+`mode = "edit"` (reads the source file's raw contents at plan time and uses them as a block — a dotdrift convenience since mise's `source` alone is a whole-file entry), and `source`+`template` (a rendered block, e.g. `template = "tera"`, mise renders at apply time). The first, second, and fourth mirror mise's vocabulary exactly (https://mise.jdx.dev/dotfiles.html, "Edit entries"). End-to-end: parse (`profile.Dotfile` gains `Line`/`Block`/`Comment`/`Template` + `IsEdit()`) → resolve (`resolve.DotfileEntry` mirrors them; `SplitEditTarget` + `validateEditEntry` enforce the rules; `mergeDotfiles` branches edit vs whole-file, translates `mode = "edit"` to an inline block by reading the source file, and skips source resolution for inline line/block edits; `checkDotfileConflicts` rejects an edit on a file another module claims whole-file) → emit (`mise.GenerateDotfiles` switches on the form; `tomlEscaper` gains `\n`/`\t`/`\r` so multi-line blocks survive as TOML basic strings; round-trips byte-identical through BurntSushi) → drift (`drift.checkDotfileEdit` probes the live file directly: exact line match, marker-delimited content compare, or marker-presence-only for template — bypassing `ResolveBootstrapFiles`) → plan (`cmd/plan.go` renders `line:`/`block:`(+`comment:`)/`source:`+`template:` in text and JSON) → onboard (re-onboarding a module with hand-written edit entries round-trips them verbatim instead of collapsing to empty source/mode). Edit entries work at **either scope**, like whole-file entries: user-scope edits apply as the invoking user (`mise dotfiles apply`); system-scope edits (e.g. `/etc/hosts/dev`) apply via elevated `mise dotfiles apply` (`sudo`) — `systemFilesStep` was extended to split system entries by kind (whole-file → `[bootstrap.files]` via `mise bootstrap --only files`; edit → `[dotfiles]` config via `DotfilesApplySudo`), since `[bootstrap.files]` does file placement, not in-place edits. New contract invariant #18; `docs/product/profile-layout.md` documents the four forms, validation rules, and per-key layer merge.
