* **Fixed (field-edit caret reset strips the row color from the tail — issue [0102](issues/0102-tui-caret-reset-strips-row-color.md))**: editing a package line (or any inline field), moving the caret left into the text lost the text's accent color and moving it back to the end restored it. Root cause, proven by a byte-level probe of the render: `editLines` nests the 0092 block caret inside the cursor-row render, and lipgloss closes every styled run with a full reset (`ESC[m`), so the caret's own reset killed the row's bold+fuchsia for everything after it — at the end of input the reset trails the last cell and nothing follows, which is why the color came back there. The fix is at the shared point: a new `theme.caretCell` swaps the caret's closing full reset for `ESC[27m` (reverse off) — the caret releases only the attribute it sets and the enclosing row style carries on — and all three caret render sites route through it (the workspace field editor, the multi-line editor's caret line, the picker's location bar), so the invariant holds for future nestings too. `caretCell` accepts both reset spellings (`ESC[m`, `ESC[0m`), so a dependency upgrade cannot silently reintroduce the bug. * **Fixed (nav filter settles the workspace on the selection after a debounce — issue [0101](issues/0101-tui-navfilter-settles-details-debounce.md))**: quick-filtering the modules list left the details pane on the previously selected module. The root cause: `navFilterKey`'s query-changing paths (typed characters, backspace) and the compositor's paste path called `refilter` — which moves the cursor — and returned `nil`; only `j`/`k`/arrows and `esc` synced the workspace, and even `enter` (which ends the typing mode with the filter applied) did not, so the stale details survived until the next nav movement. A per-keystroke `syncWorkspace` was never an option (it would spawn a layer file read per character), so the sync now rides a 300 ms debounce in the compositor's existing token pattern (`msgFadeMsg`): every query change bumps `filterSeq` and returns a `tea.Tick` carrying the sequence; the tick's `filterSettleMsg` syncs only when its sequence is still the latest. The guard also keeps a keystroke burst from spawning duplicate in-flight reads of the same file (`loadLayer` dedupes landed reads only). An empty match set settles to an empty workspace, the same `syncWorkspace` behavior an empty selection already produces; `j`/`k` within the matches stay immediate. TDD red→green: five tests compile-red on the wished-for `filterSettleMsg`/`filterSeq` API first (typing settle, backspace settle, paste settle, empty-match settle, stale-tick guard; the first legs also pin that typing does NOT sync per keystroke), then green.
