## 2026-08-06

* **Improved (apply, tool output)**: called-tool output (mise install/dotfiles/bootstrap/hooks, package-manager remove) now streams live to the terminal with its native colors when interactive, instead of being captured and jammed into error values / zerolog `error=` fields. New `executil.IsTerminal` (char-device check, mirrors `IsStdinTerminal`) plus `executil.StreamLive(verbose, out, err)` decide whether a child streams or is captured: stream under `--verbose` (the set -x `+ argv` trace) **or** whenever both destinations are terminals (an interactive apply); a non-verbose, piped run still captures so a failure carries self-contained diagnostics. `mise.runOp` and `packages.RunStream` now wire the child's fds straight to the terminal on that path, so the child keeps its own color output and a streaming failure returns a bare one-line error (the output is already visible) — zerolog warns (optional-hook, package-remove) and `main.go`'s bold-red error thus stay clean one-liners interactively rather than swallowing multi-line tool output. The `+ argv` echo stays a `--verbose` affordance and is omitted from the interactive default. Follow-up gap: the nested `dotdrift paru` plugin subcommand still captures paru's own output (`internal/paru`), so paru-specific color depends on mise's task-FD handling and is not yet wired.

* **Feat (hooks, optional)**: a single hook can opt out of fail-fast, and required/optional hooks interleave freely in one phase. `module.toml` accepts three equivalent spellings — the compact inline table in the array (`pre = ["...", { command = "...", optional = true }]`, recommended for one-off optional hooks), the verbose table-array `[[hooks.pre]] command = "..." optional = true`, and the legacy string array (`pre = ["..."]`, all required); a custom `UnmarshalTOML` accepts both a string and a table element so all three work and existing profiles are unchanged. `profile.HookCommand{Command, Optional}` flows through `resolve.HooksStep` (aggregation preserves order + per-command flags) into `mise.HooksStep`, which runs each command as its own mise task (`hooks-pre-<i>`, emitted in lockstep by `GenerateHookTasks`) so order is preserved while a failing optional hook is logged at zerolog `Warn` and skipped instead of aborting the step. Required-hook behavior is unchanged. `dotdrift plan` marks optional hooks (`(optional)` text, `"optional": true` JSON).
